# Runtime2 — 1.5.97 の関数範囲検出を修正（DLL 1.0.18.7）

## 今回の原因

Skyrim Outfit System 無効化後のログは `absent/ambiguous hair mask call` で停止していました。
利用者の許可を得て、起動中の 1.5.97 を読み取り専用で確認しました。
髪マスクの呼出先は本来の SkyrimSE.exe 内の処理のままで、ここは別 MOD に書き換えられていませんでした。

Runtime1 は Windows の関数情報の先頭区間だけを検査していました。
実際にはこの関数が複数区間に分割されており、必要な CALL は後続区間にありました。
こちらの探索範囲の扱いが原因です。

## 修正

UNW_FLAG_CHAININFO を辿り、同じ親関数に属する連続区間を含めて命令を解析します。
単に次の関数まで走査範囲を広げる方法ではありません。隣の独立した関数、循環した区間情報、読めない情報、過大な範囲は受け入れません。
既存の呼出先・visitor・IED チェーン検証は維持します。
通常着替え、描画本体、一人称、フォロワー、保存復元、UI、初期値は変更していません。
Runtime1 とそれ以前の作業は保持しています。

仕様の参照：[Microsoft — x64 exception handling / Chained unwind info](https://learn.microsoft.com/en-us/cpp/build/exception-handling-x64?view=msvc-170#chained-unwind-info-structures)

## 確認結果

- ビルド成功、43/43 テスト成功、DLL バージョンと 7 対象の許可リストを照合済み。
- 取得した 1.5.97 の実メモリデータを修正後の解析へ渡し、髪マスクの呼出箇所を一意に特定できることを確認。
- 重ね着側の CALL はトランポリンを経由しています。その先の実メモリは今回の保存データに含まれないため、連携検証の最終結果は次回起動ログで確認します。
- この DLL でのゲーム内適用・解除は未確認。他バージョンも引き続き実機未検証です。

開発用の照合値：髪マスク親 RVA 0x362E90、最初の区間終端 0x362EBB、同一関数の連続区間終端 0x362FFA。
CALL は RVA 0x362F0C にあり、本来の GetWornMask（RVA 0x1D9040）を呼んでいます。
これらのアドレスは証拠記録であり、DLL の接続位置を固定するためには使用していません。

## お試しいただく手順

1. ゲームを終了し、Runtime1 の代わりに Runtime2 を有効にします。同時に有効にする必要はありません。
2. Skyrim Outfit System は無効のまま、1.5.97 を起動してください。設定ファイルの変更は不要です。
3. まず重ね着ボタンを選択できるか確認してください。
4. 選択できた場合はプレイヤーの一人称／三人称、フォロワーの適用と解除を確認してください。
5. 成否にかかわらず、その起動の OutfitGallery.log を確認します。

成功時は `RUNTIME2 transmog hooks installed on ...` が出ます。
選択できなければ `RUNTIME2 function ...` と停止理由から、次の箇所を切り分けます。
